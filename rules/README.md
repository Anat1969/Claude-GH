# כללים קבועים: הזיכרון המשותף של כל השיחות

שיחות של Claude לא רואות זו את זו.
מה שמשותף לכולן הוא רק מה שכל שיחה **טוענת בהתחלה**.
לכן כל הנחיה קבועה של ענת נכנסת לכאן פעם אחת, וכל שיחה קוראת אותה מכאן.

## חמשת התחומים

| קובץ | מה נכנס אליו |
|---|---|
| `language.md` | שפה, טון, מבנה תשובה, מייל |
| `narrative.md` | סיפור, מאמר, כתבה, פוסט, ריכוז ידע, פרומפט ויזואלי |
| `schemas.md` | תבניות חשיבה, מבני תשובה ומבני נתונים |
| `ux.md` | חוויית משתמש: זרימה, לחיצות, מצבים, הסברים |
| `design.md` | הפניה בלבד לסקיל העיצוב. לא מעתיקים אותו |

כלל שנוגע לבניית אפליקציה נכנס ל-`CLAUDE.md` ולסקיל `anat-app-builder`, ולא לכאן.
כלל של אפליקציה אחת נכנס ל-CLAUDE.md של הריפו שלה.

## הפרוטוקול: איך כלל נכנס

1. **זיהוי:** הנחיה עם "תמיד", "אף פעם", "בכל", או תיקון שחוזר על עצמו היא מועמדת לכלל.
   Claude שואל בשורה אחת: "כלל קבוע? תחום: <תחום>".
   הודעה שמתחילה ב-"כלל:" נכנסת בלי שאלה.
2. **ניסוח:** שורה אחת, בציווי, עם תאריך ומקור: `- <כלל>. (DD.MM.YYYY, <נושא השיחה>)`
3. **כתיבה לפי סוג השיחה:**
   - **Code:** קומיט מיד לקובץ התחום ב-Claude-GH, ומיזוג ל-main.
   - **Chat ו-Cowork:** קובץ טקסט חדש בתיקיית Drive בשם `Claude-GH תור כללים`.
     שם הקובץ: `<תחום> YYYY-MM-DD <3 מילים>`. התוכן: שורת הכלל המנוסחת.
     אם התיקייה לא קיימת, יוצרים אותה. אם אין גישה ל-Drive, מציגים לענת את השורה כטקסט מוכן להדבקה ואת שם הקובץ שאליו היא שייכת.
4. **ריקון התור:** בתחילת כל שיחת Code ב-Claude-GH, ובחלון הלילי, קוראים את התיקייה, מכניסים כל כלל לקובץ התחום, ומעבירים את קובצי התור לתת־תיקייה `נקלט`.
5. **סתירה:** כלל חדש שסותר כלל קיים **מחליף** אותו. את הישן מוחקים, ובסוף הקובץ רושמים שורה ב"הוחלף".

## רענון בשיחה פתוחה

- "רענן כללים": קוראים מחדש את כל הקבצים כאן ואת תיקיית התור, ומציגים בשורה אחת מה חדש.
- לפני כל מסירה בודקים אם `rules/` השתנה מאז תחילת השיחה.

## בדיקה שהמנגנון חי

בתחילת שיחה, כשענת שואלת "מה אתה יודע?", Claude מונה את מספר הכללים בכל תחום ואת התאריך של הכלל האחרון.
